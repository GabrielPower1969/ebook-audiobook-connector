### 第 7 步的清单（新增，之前没写过）

**安全**
- Cloudflare Access 在最前面；Worker 侧再验一次 JWT（不信任「前面挡过了」）
- 所有写接口校验 `Origin` / `Sec-Fetch-Site`，防 CSRF
- 上传/导入只走 Mac 侧，Worker 不接受任何用户上传
- 速率限制：Cloudflare Rules，按 IP + 账号
- 密钥只进 Worker Secrets，永不进仓库；仓库私有也一样

**防污染**（内容与索引不被外部搞脏）
- 数据库唯一真相是 `library.json` + 内容哈希，导入时校验 sha256，对不上就拒绝
- 任何用户输入（笔记、书单名）落库前转义，渲染时不用 `innerHTML` 拼接
- 生词本、进度这类用户数据按账号隔离，Worker 侧强制 `WHERE user_id = ?`
- 派生物（封面、转写、对齐）全部可从源文件重建，被污染就整目录删掉重跑

**SEO**（注意：书的内容是私有的，能公开的只有「壳」）
- 公开页只有：首页、关于、方法论/博客。**书目和正文一律 `noindex` 且在 Access 后面**
- 首页做 server-rendered HTML（Worker 直出），不靠 JS 才能看到内容
- `sitemap.xml`、`robots.txt`、canonical、hreflang（zh-CN / en）
- Open Graph + Twitter Card，配一张品牌图
- JSON-LD：`WebSite` + `SoftwareApplication`；**不要**给私有藏书打 `Book` 结构化数据
- 十句名言可以做十个内容页（`/quotes/portable-magic` 之类），这是唯一天然适合 SEO 的素材

## 六、收费与报税（2026-09-10 调研）

### 6.1 ⚠️ 收费之前必须先解决的问题

**现在库里的有声书是商业出版物，没有分发权。** 自己听是一回事，**收费提供**是另一回事——
那是在卖别人的版权作品，不是灰色地带。要做成能收钱的产品，内容只能是三者之一：

| | 说明 |
|---|---|
| 公版书 | Gutenberg / LibriVox，没有版权问题（富兰克林自传就是 LibriVox 的） |
| 自有内容 | 自己写、自己录，或买断授权 |
| **纯工具** | 用户上传**自己的**书和音频，我们只提供对齐和阅读器——**这条最现实** |

第三条是这个产品的天然形态：核心价值是对齐管线和阅读器，不是藏书。

### 6.2 Stripe 还是支付宝

| | 结论 |
|---|---|
| **Stripe** | 支持新西兰主体收款 `[B · stripe.com/global 列出 New Zealand]`。**推荐** |
| **支付宝** | **通过 Stripe 就能收**，是 Stripe 的一种支付方式 `[A · docs.stripe.com/payments/alipay]`。不用单独对接 |
| 具体费率 | 定价页是 JS 渲染，**没抓到数字** `[D · 待核实]`。签约前自己看 stripe.com/nz/pricing |

**结论：只接 Stripe 一家，把支付宝当作 Stripe 里的一个支付方式打开。** 中国用户用支付宝、
海外用户刷卡，一套后台、一份对账。单独去对接支付宝国际版要公司主体和更长的审核，不值得。

### 6.3 「BNZ 账户自动报税」能做到吗

**不能直接做到——新西兰没有「银行账户 → 自动报税」这条通路。** 报税走 IRD 的 myIR，
银行不参与。但有两条接近的路：

| 方案 | 自动到什么程度 | 适合 |
|---|---|---|
| **Hnry** | 收款进 Hnry 账户，**它在收到钱的当下就扣掉所得税 / ACC / 学生贷款 / GST 并代缴给 IRD**，报税表也替你报。费用「自雇收入的 1% + GST」`[B · hnry.co.nz]` | 个体户（sole trader），最接近「自动报税」 |
| **Xero + BNZ 银行数据直连** | 银行流水自动进账，GST 申报表在 Xero 里生成并**直接提交 IRD**，但要你点确认 | 有公司主体、要正经做账 |
| 自己报 | myIR 手工填 | 收入很少时 |

三条都不是「连上 BNZ 就自动了」。Hnry 最省心，代价是抽 1%。

**还有一条大多数人会忽略的**：**年营业额不到 NZ$60,000 不用注册 GST**
`[A · ird.govt.nz/gst/registering-for-gst · 核实 2026-09-10]`。
这个产品早期大概率远低于这个数，那么 GST 这一整块可以先不用管。
另外把数字服务卖给海外客户，GST 处理和卖给本地不同（出口服务通常零税率），
这条我**没核实到原文** `[D]`，真要收海外的钱之前得查清楚。

### 6.4 我的建议

先别做收费。**先把产品做成「工具」形态**（用户带自己的书），域名和账号系统本来就要做；
等真有人愿意付钱了，再接 Stripe——那时候一天就能接上，而版权和 GST 的问题必须在收第一块钱
之前想清楚，不是之后。
